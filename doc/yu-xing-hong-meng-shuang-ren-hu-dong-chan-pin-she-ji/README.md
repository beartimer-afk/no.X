# 产品总览｜余兴

> 当前阶段：产品经理 / 设计阶段。先定义产品、机制、交互与视觉，不进入代码实现。

## 一句话定义

**两个人、共用一台手机、内容可自定义，由 App 负责制造悬念、决定输赢并组织挑战的私密互动游戏引擎。**

它不是情侣社交 App，也不是以成人内容为产品表层的 App。情侣、喝酒、聚会、搞笑、旅行等只是不同内容包或规则预设；产品真正的核心是现场互动机制。

## 核心使用前提

* 默认两个人面对面。
* 默认只有一台手机，轮流操作。
* 不依赖双方各自安装 App。
* 不需要好友、聊天、双账号配对、消息同步或双设备联机。
* 手机扮演的是“神秘裁判 + 游戏主持人 + 挑战管理器”。

## 核心循环

**制造悬念 → 决定执行者 / 输家 → 抽取挑战 → 当场完成 → 可选验收 → 进入下一轮。**

决定执行者的方式只是游戏机制，可以包括：

* Bomb / 随机炸弹
* 骰子
* 转盘
* 反应速度
* 猜数字
* 记忆小游戏
* 石头剪刀布
* 简短 PK
* 纯随机

因此，“炸弹”不是产品本身，只是一个高潜力的判定器。

## 核心差异化 1：Secret Match / 秘密选择

这是当前最重要的产品机制之一。

流程：

1. 玩家 A 单独拿手机，对一组挑战选择“接受 / 可以尝试 / 不接受”。
2. App 遮挡结果，提示把手机交给玩家 B。
3. 玩家 B 完成同样的私密选择。
4. App 只计算双方的共同接受集合。
5. 后续游戏只从这个集合中抽取挑战。

结果只显示类似：

> 你们匹配了 16 个挑战。

A 不知道 B 具体拒绝了什么，B 也不知道 A 具体拒绝了什么。这个机制既可以包装成“默契匹配”，也天然适用于需要确认双方边界的私人场景。

## 核心差异化 2：悬念型小游戏

App 相比实体酒瓶、骰子等工具真正能增加的价值，不只是随机，而是**过程中的不可预测性和情绪张力**。

例如 Bomb：

手机在两个人之间传递，双方都不知道炸弹何时爆炸。震动、声音、动效、假震动、节奏变化都可以制造持续压力。

因此需要重点设计：

* 未知时间点
* 不确定输家
* 结果揭晓
* 触觉反馈
* 音效反馈
* 视觉节奏

## 核心差异化 3：用户自定义 Challenge Pack

内容与引擎必须彻底分开。

### 引擎层

App 负责：

* 随机系统
* 输赢判定
* Secret Match
* 共同挑战池
* 权重与难度
* 倒计时
* 挑战执行
* 对方确认
* 录音 / 拍照 / 录像能力
* 本地记录
* 自动销毁
* Pack 管理

### 内容层

内容全部数据化：

* 搞笑包
* 默契包
* 聚会包
* 酒局包
* 情侣包
* 用户私人自定义包

成人内容不作为官方内置内容。**成人部分如果存在，只是用户自己创建的数据包 / 自定义挑战内容。** App 不需要理解挑战文字本身的语义。

一个挑战可包含：

* 标题
* 描述
* 执行者
* 难度
* 权重
* 是否限时
* 是否需要录音
* 是否需要拍照
* 是否需要录像
* 是否需要另一方确认
* 失败后的处理方式

## 媒体能力定位

因为两个人就在现场，所以拍照 / 录音 / 录像不应被强行定义为“完成证明”。另一方本身就能看到任务是否完成。

媒体能力更适合作为：

1. **挑战本身的一部分**：录一句话、拍一张照片、录一段视频；
2. **可选验收方式**：对方确认、计时结束、照片、录音、录像。

隐私原则：

* 默认本地处理；
* 不自动进入系统相册；
* 保存动作必须明确；
* 可提供游戏结束自动删除；
* 可提供阅后即焚；
* Face ID / 私密空间可作为高级能力。

## 玩家与人数

产品当前核心仍然是“双人 + 一台手机”。

基础玩法不应该因为“酒局 / 聚会”场景就被迫引入复杂玩家系统。只有计分、排行、淘汰、指定玩家、每人独立任务池等能力真正需要时，才增加玩家身份。

第一版避免因为多人可能性而扩大范围。

## 场景的正确位置

“情侣 / 喝酒 / 聚会 / 搞笑”等不是首页产品定位，应放在 Pack 或 Settings 中，作为内容与规则预设。

首页应该尽可能直接：

* START
* Packs
* Create
* Settings

现场游戏的启动步骤越少越好。

## “酒瓶子”场景带来的真正启发

酒局不是核心产品方向，它只是帮助发现了一个用户问题：

> 传统随机玩法虽然随机，但缺少足够的过程悬念。

转酒瓶子可以看到结果逐渐发生；数字骰子也很快结束。手机则可以通过不可预测的时间、震动、声音、动画和假反馈持续制造悬念。

因此值得保留的是**悬念设计**，而不是把产品改造成多人喝酒 App。

## “输家控制下一轮”机制

从“谁炸了谁喝，喝的人制定下一轮挑战”中提炼出的真正价值是：

> **输家在完成挑战后，获得下一轮的一部分控制权。**

可能的权力：

* 选择下一轮小游戏；
* 选择两个挑战让对方二选一；
* 修改一个规则；
* 临时创建下一个挑战；
* 调整下一轮难度。

这样形成“系统制造随机性 + 玩家创造内容”的循环，避免 App 变成机械发牌器。

## UI / UX 原则

UI 是产品核心竞争力之一，不是包装层。

产品本质是：

* 情绪产品
* 现场体验产品
* 游戏产品

目标气质：

**高级、克制、神秘、私密 + 轻游戏感。**

避免：

* 廉价成人 App 感；
* 儿童派对游戏感；
* 默认组件堆砌的工具感。

重点体验节点：

* 手机交给另一人的过渡
* 私密选择出现与隐藏
* 卡片翻开
* 倒计时
* Bomb 紧张阶段
* 爆炸 / 输家揭晓
* 挑战揭晓
* 媒体记录
* 下一轮开始

真正拉开品质差距的是：**字体、间距、卡片、动效、震动、音效、节奏与留白共同组成的情绪系统。**

## 第一版建议范围

第一版保持极度克制：

1. START
2. 一个做得足够漂亮的 Bomb 游戏
3. 决出输家
4. 抽取 Challenge
5. 用户可创建 Challenge
6. 完成后进入下一轮
7. Secret Match

拍照、录音、录像、复杂 Pack 系统、多人、排行榜和大量小游戏都可以后置。

## 当前最需要保护的三个产品资产

1. **Secret Match：双方私密选择，只暴露共同接受集合。**
2. **悬念型小游戏：手机负责制造现实工具无法提供的未知性与情绪张力。**
3. **用户自定义 Challenge Pack：引擎与内容彻底分离。**

这三者组合后，产品已经不再是普通 Truth or Dare，而是一个具有独立产品逻辑的“双人现场互动引擎”。
