# 04｜Secret Match 规格

## 1. 目标

Secret Match 不是问卷，而是一种**在同一台手机上完成的双盲内容筛选机制**。

它同时解决：

* 不想直接暴露拒绝项；
* 想制造“双方到底匹配了什么”的期待；
* 只让双方都接受的挑战进入游戏。

## 2. 入口

Secret Match 是 START 后的可选模式，也可从 Pack 详情启动。

Quick Start 永远存在，避免每次开局强制筛选。

## 3. 玩家 A

### 3.1 Privacy Gate

首先显示：

> 只给第一位玩家看
>
> 准备好后继续

按钮：**我准备好了**。

### 3.2 逐张选择

一次只显示一个候选挑战/主题。

动作：

* 愿意；
* 可以试试；
* 跳过。

第一版匹配规则：

* 愿意 + 愿意 → Match；
* 愿意 + 可以试试 → Match；
* 可以试试 + 可以试试 → Match；
* 任一方跳过 → 不进入池。

不设计复杂权重，先保证可理解。

### 3.3 完成 A

不显示“你拒绝了多少”。

显示：

> 已记录
>
> 把手机交给另一位玩家

随后进入视觉遮挡页。

## 4. Hand-off Gate

交接页必须做到即使 A 还拿着手机，也无法快速返回偷看 B 的界面。

推荐交互：

* 全屏遮挡；
* 文案“交给下一位玩家”；
* 长按 1 秒“我是下一位玩家”进入；
* 进入后禁止普通返回到 A 的选择结果；
* 若强制退出 Secret Match，只允许整次重新开始。

## 5. 玩家 B

流程与 A 相同。

B 不知道 A 的任何具体选择状态。

## 6. Match Result

只显示正向结果：

> **匹配到 18 个挑战**

可以显示抽象的分布，例如：

* 轻松 8
* 大胆 6
* 极限 4

但前提是不会反推出谁拒绝了什么。

禁止显示：

* A 拒绝 X 个；
* B 拒绝 X 个；
* 哪一方否决某一项；
* “差一点匹配”的具体条目。

## 7. 候选内容颗粒度

第一版优先使用“具体 Challenge”逐条筛选，而不是只筛标签。

原因：标签“大胆/拍照/身体接触”等理解差异过大。

未来可在 Challenge 太多时增加两层筛选：先主题，再具体挑战。

## 8. 数量不足

匹配结果：

* ≥10：正常开始；
* 5–9：可以开始，但提示内容较少，重复概率会增加；
* 1–4：建议返回增加选择，也允许继续；
* 0：不能进入随机挑战循环，提供“重新选择 / 换 Pack / Quick Start”。

## 9. 隐私

Secret Match 原始选择默认只存在当前 Session 内存/临时存储中。

Session 结束后删除双方逐项原始选择，只保留用户明确要求保存的 Pack 设置；默认不做“长期偏好画像”。
