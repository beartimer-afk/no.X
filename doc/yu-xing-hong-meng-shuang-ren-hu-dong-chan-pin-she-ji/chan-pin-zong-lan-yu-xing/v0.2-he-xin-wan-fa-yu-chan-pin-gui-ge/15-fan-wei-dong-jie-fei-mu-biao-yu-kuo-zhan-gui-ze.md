# 15｜范围冻结、非目标与扩展规则

## 1. v0.2 产品核心不可被扩展需求改变

任何新需求都必须回答：它是否强化以下三件事？

1. Secret Match / 私密共同选择；
2. Suspense / 现场悬念；
3. Challenge Pack / 用户自定义内容。

如果不能强化，默认后置。

## 2. 第一版明确非目标

* 多人社交网络；
* 双手机联机；
* 好友关系；
* 聊天；
* 账号体系；
* 云端情侣空间；
* 排行榜；
* 内容社区；
* 公开 UGC；
* 远程 Pack 商店；
* 官方成人内容；
* 大量小游戏数量竞争；
* 复杂积分/等级/成长系统。

## 3. 酒局/聚会扩展原则

喝酒只是 Pack / Rule Preset，不改变首页和核心状态机。

如果未来增加多人：

* 基础 Bomb 仍可不知人数；
* 只有计分/指定玩家等功能需要 Player Model；
* Player Model 必须作为可选层，不反向污染双人 Quick Start。

## 4. 新小游戏接入规则

所有小游戏都必须输出同样的标准结果：

* executor / loser；
* optional metadata；
* end reason。

然后进入统一 Lose Reveal → Challenge 流程。

小游戏不能自行内置另一套 Challenge 页面，否则体验会碎裂。

## 5. 新 Challenge Type 接入规则

新类型必须仍支持：

* Reveal；
* Start/Execute；
* Skip；
* Complete；
* 中断恢复；
* Session 清理。

例如未来加入语音识别、姿势检测，也不能取消用户“换一个”的权利。

## 6. 商业化边界

付费卖能力，而不是依靠低质题库数量：

* 高级 Pack 创作；
* 高级规则；
* 媒体能力；
* 私密空间；
* 高级游戏模式；
* 主题/视觉；
* 导入导出。

免费版必须能完整玩完核心循环，不能把“完成一轮”拆成付费墙。

## 7. 决策优先级

遇到冲突时按以下顺序决策：

**现场可玩性 > 隐私/边界 > 情绪节奏 > UI 一致性 > 功能数量 > 配置自由度。**

例如一个设置虽然更灵活，但让 START 多出三步，就应该后置。
