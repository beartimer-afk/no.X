# 21｜3B 失败排查手册：禁止边猜边改

## 规则

一个验收失败时，先归类，再改。禁止“看起来像哪里不对就重构”。

## 类型 1：构建失败

固定步骤：

1. 保存原始错误全文；
2. 找到第一条真正编译错误，不要先处理连锁错误；
3. 只修改引发该错误的文件；
4. 重编译；
5. 重复直到 Build PASS；
6. 不改变 UI 规格。

## 类型 2：页面位置不对

1. 截图标注错误组件；
2. 检查父容器 padding；
3. 检查本组件 margin；
4. 检查 SafeArea；
5. 只改最小层级；
6. 禁止通过整个页面 scale 缩放来掩盖。

## 类型 3：状态跳错

1. 打印当前 state；
2. 打印触发 event；
3. 打印 expected state；
4. 检查唯一状态切换位置；
5. 禁止加第二套“临时 boolean”绕过状态机。

例如禁止：

```
isBoomPage = true
showLose = true
```

代替 `state = LOSE_REVEAL`。

## 类型 4：Bomb 时间不准

只检查：

* monotonic clock；
* bombStartAt；
* bombExplodeAt；
* 前后台修正；
* 新 holder 安全窗。

禁止改 14–30s 常量来“让测试好过”。

## 类型 5：Explosion 卡顿

按顺序：

1. 是否同步 IO；
2. 粒子是否 >16；
3. 是否加载超大纹理；
4. 是否每帧创建对象；
5. 先减粒子到 8；
6. 仍卡再报告 `PERF_GAP`。

**不得删除 Vacuum，不得缩短总节奏来解决性能。**

## 类型 6：UI 不像参考图

先对照 Token 和结构，不允许直接重新“设计”。

检查：

* 黑/暗紫背景是否正确；
* 粉紫是否够鲜艳；
* 背景摄影是否过亮；
* Core 是否是小圆核而非炸弹；
* 是否多了系统默认组件风格。

## 类型 7：需求文档互相冲突

按权威优先级处理；若同一 v0.5 任务内部冲突，报告 `SPEC_GAP`，停止该项。
