# v0.4｜实现启动与开发交付基线

> 状态：设计探索结束，进入实现阶段。

## 1. 当前实现目标

第一目标不是“把所有页面做完”，而是做出一个**可以在鸿蒙真机上连续玩 5–10 分钟的核心闭环**：

**Home → Round Ready → 按住圆核 → 边说边按 → PASS → 爆炸 → 输家揭晓 → 挑战揭晓 → 完成/换一张 → 下一轮。**

如果这一条链路不好玩、不紧张、不好看，则暂停外围功能开发，优先修核心体验。

## 2. 当前产品定义

NO.X 是一个两个人面对面、共用一台手机玩的成人 Bomb Game。

第一版不需要把产品解释成通用派对引擎，不需要优先照顾多人、喝酒、社交、账号、云端等场景。

成人挑战内容属于数据层；引擎负责游戏与展示。

## 3. 当前视觉方向冻结

当前用户已认可的视觉方向：

* 品牌名：**NO.X**
* 参考气质：**Wild 风格继续向更骚、更暧昧方向发展**
* 主背景：深黑 / 暗紫
* 主高光：霓虹粉
* 辅助高光：紫色
* 强对比、高饱和、夜晚感、数字感
* 可出现亲密人物氛围图，但不得遮挡关键游戏信息
* UI 要像成熟成人情侣游戏，不做儿童 Party Game
* 不回到早期的黑金奢华路线
* 不回到纯蓝赛博硬核路线

### 核心视觉符号

**小圆核 / 小圆圈必须保留。**

它是 Bomb 的按压对象，也是 NO.X 的核心互动符号。

禁止替换为：

* 卡通炸弹
* 大型科幻能量球
* 复杂机械炸弹
* 手指插画

## 4. 第一版核心交互冻结

玩家拿到手机后：

1. 看到当前 Prompt；
2. 必须按住中央小圆核；
3. 按住期间边说/回答 Prompt；
4. 同时承担随机爆炸风险；
5. 达到最小按压条件后 PASS 解锁；
6. 玩家松手并把手机交给对方；
7. 任意持有阶段均可能爆炸；
8. 爆炸后当前持有者输；
9. 显示输家揭晓；
10. 显示成人 Challenge；
11. 完成或换一张；
12. 下一轮。

### 设计目的

让玩家同时分配注意力给：

* 手指持续按压；
* 嘴上回答/说话；
* 对爆炸时间的担忧。

这个“三线程压力”是核心刺激来源，开发不得简化为单纯点击后等待。

## 5. 第一版明确不做

* 双手机联机
* 账号系统
* 社交关系
* 聊天
* 云端同步
* 排行榜
* 多人复杂玩家系统
* AI 语义判定用户是否真的说完
* 复杂语音识别
* 公开成人内容市场
* 大量小游戏

## 6. 实现优先级

### P0：必须先完成

* Home
* Round Ready
* Bomb Pressing
* Bomb Tense
* PASS
* Random Explosion
* Lose Reveal
* Challenge Reveal
* 下一轮
* 触觉反馈
* 基础声音
* 本地 Challenge 数据

### P1：核心闭环通过后

* Challenge 编辑
* 数据包切换
* Settings
* 换一张
* 简单历史统计

### P2：后续

* Secret Match
* 媒体挑战
* 更多 Bomb Rule
* 更多小游戏
* Pack 导入导出

## 7. 开发阶段原则

所有页面必须先对照 v0.3 UI 规格实现，再允许工程侧调整。

工程为了方便不得擅自：

* 换颜色体系；
* 换字体层级；
* 把圆核改成普通按钮；
* 把爆炸改成 Toast；
* 把挑战改成普通列表；
* 删除触觉；
* 删除按压过程；
* 加底部 Tab Bar；
* 给首页堆入口。

产品体验优先于工程省事。
