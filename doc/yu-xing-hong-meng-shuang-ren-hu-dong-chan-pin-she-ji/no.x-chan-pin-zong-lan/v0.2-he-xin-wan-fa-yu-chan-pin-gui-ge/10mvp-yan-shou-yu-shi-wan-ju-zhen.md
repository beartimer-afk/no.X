# 10｜MVP 验收与试玩矩阵

## 1. MVP Definition of Done

不是“页面能打开”就算完成。第一版必须完成一个从 START 到至少连续 5 轮、再正常结束的完整 Session。

## 2. 功能验收

### Quick Start

* 首次启动可在极少步骤内开始；
* 二次启动 START 直接沿用最近配置；
* 不强制输入人数/姓名/关系。

### Bomb

* 安全起步正常；
* 随机时长在目标分布内；
* PASS 有最小持有交互；
* Fake Signal 不违反频率约束；
* 真爆炸触觉/视觉/声音同步；
* 切后台后暂停且恢复安全；
* 20 局连续试玩中不存在明显可预测节奏。

### Challenge

* 结果与 Challenge 分两步揭晓；
* Challenge 可换一个；
* 连续换 3 次可降低强度；
* Session 内不高频重复同一 Challenge；
* 完成后能自然进入下一轮。

### Secret Match

* A 无法看到 B 选择，B 无法看到 A 选择；
* 普通返回不能跨越 Hand-off Gate；
* 结果只显示共同集合；
* 0 个匹配时有完整恢复路径；
* Session 结束后原始选择被清理。

### Pack / Create

* 用户可在 30 秒内创建一个最简单 Challenge；
* 新 Challenge 可立即进入 Pack 并被抽取；
* 删除可撤销。

### Media

* 权限按需请求；
* 媒体默认不进系统相册；
* Session 结束可删除临时媒体；
* 中断不会误标完成。

## 3. 视觉验收

每个核心屏幕截取真实设备截图，检查：

* 视觉焦点是否唯一；
* 主文案是否 1 秒内可理解；
* 是否出现无意义技术信息；
* 是否存在默认组件拼凑感；
* Challenge 长文本是否破版；
* 小屏/大屏安全区是否正常；
* 黑暗环境下是否刺眼。

## 4. 动效验收

用屏幕录制逐帧检查：

* PASS 响应无明显延迟；
* Fake 与 Explosion 强度层级明显；
* 爆炸主动画 <1 秒；
* Lose Reveal 不与 Challenge 同时抢焦点；
* Challenge 翻牌没有跳帧/布局闪烁；
* 减少动态效果模式可正常完成全部流程。

## 5. 试玩脚本

### Script A：第一次使用

参与者完全不知道规则。观察是否能在无解释情况下开始并玩完 3 轮。

### Script B：连续 10 轮

检查是否开始觉得节奏机械、Fake Signal 失去可信度、Challenge 重复。

### Script C：频繁换挑战

连续 Skip，验证产品是否保持尊重且不会卡死。

### Script D：后台中断

Bomb 运行时切后台、锁屏、接通知，再恢复。

### Script E：权限全部拒绝

验证普通玩法仍完整可玩。

### Script F：Secret Match 偷看测试

刻意尝试返回、切后台、任务切换，确认无法轻易看到另一位选择。

## 6. 情绪验收

这是最高优先级的非功能指标。试玩后只问几个问题：

* 爆炸前有没有紧张？
* 有没有想快点把手机交出去？
* 输家出现时有没有一个清晰的“啊，是你”瞬间？
* Challenge 翻开前有没有第二次期待？
* 完成一轮后是否自然想再来一轮？
* 有没有任何页面让人觉得尴尬、廉价、像低质真心话大冒险？

如果功能全部通过，但这些答案大多是否定，MVP 仍然不算通过。

## 7. 第一版退出条件

满足以下条件才进入更多小游戏开发：

1. Bomb 单玩法连续 10 轮仍可玩；
2. Secret Match 单手机隐私交接成立；
3. Challenge 自定义闭环成立；
4. UI/触觉/音效形成统一气质；
5. 真实设备上的 Session 能稳定结束与恢复。

在此之前不扩多人、不做社区、不做远程 Pack 商店、不堆小游戏数量。
