# v0.2｜核心玩法与产品规格

> 本章把“余兴”从产品共识继续向下拆到可设计、可开发、可试玩、可验收的规格层。默认目标设备为手机，核心场景为两个人面对面共用一台手机。

## 设计总原则

余兴不是题库 App。它的核心工作是**控制现场节奏与未知感**。

每一轮必须完成：

**制造悬念 → 产生结果 → 触发挑战 → 完成/跳过 → 给下一轮一个新变量 → 无缝继续。**

用户真正期待的是三层未知：

1. **什么时候发生？**
2. **发生在谁身上？**
3. **发生后要做什么？**

因此交互优先级不是“最快告诉用户结果”，而是“让结果出现之前的等待本身变得有趣”。

## 默认产品路径

### Quick Start

**打开 App → START → 直接进入第一轮。**

默认使用：最近一次 Pack、最近一次游戏、最近一次规则。第一次使用时使用官方安全默认值。

不询问：人数、姓名、关系、场景。

### Secret Match

**START → Secret Match → A 私密选择 → 交接手机 → B 私密选择 → 计算共同池 → 游戏。**

它是可选开局，不应强制每次执行。

## 单轮核心链路

**ROUND READY → Mini Game → Lose Reveal → Challenge Face-down → Reveal → Execute / Skip → Complete → Next Move → ROUND+1**

## Session 结束

Session 默认无限持续，直到用户主动选择结束。结束时只做：

* 本次轮数；
* 游戏时长；
* 完成/跳过数量；
* 临时媒体处理。

不强制保存历史，不默认把媒体写入系统相册。

## 第一版默认冻结项

* 核心人数模型：双人、单手机；
* 核心小游戏：Bomb；
* 默认每轮 20–75 秒；
* Bomb 不显示剩余时间、不显示概率、不显示进度；
* 挑战永远允许跳过；
* 跳过不使用羞辱性文案；
* 成人内容不内置，只允许用户自定义内容；
* 默认本地数据；
* 媒体默认临时，不自动保存；
* UI 气质：高级、克制、神秘、轻游戏感；
* 核心视觉资源优先投在 Bomb、揭晓、交接、挑战翻牌和 Next Move。
