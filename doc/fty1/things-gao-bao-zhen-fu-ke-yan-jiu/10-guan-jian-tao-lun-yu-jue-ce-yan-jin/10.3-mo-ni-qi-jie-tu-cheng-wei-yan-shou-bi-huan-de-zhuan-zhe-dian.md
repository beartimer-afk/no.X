# 10.3｜模拟器截图成为验收闭环的转折点

在写 HarmonyOS 组件规格时出现了一个关键问题：即使文档写得很精确，AI 仍可能无法判断“做出来到底对不对”。

因此项目方向从：

**Spec → AI Code → 人看**

升级成：

**Things 真机证据 → Token / Golden → AI Code → HarmonyOS 模拟器 → Inspector Geometry → Screenshot Diff → Failure Report → AI Fix → VERIFIED**。

这使得颜色、尺寸和布局不再依赖模型审美。

同时明确：iPhone 与 HarmonyOS 不能整屏逐像素硬比，因为系统栏、字体 rasterization、屏幕比例不同。最终采用 Geometry hard gate + Token gate + normalized screenshot diff。

这个决定直接导致 H00 Visual Acceptance Harness 被提升到所有 UI 组件之前。
