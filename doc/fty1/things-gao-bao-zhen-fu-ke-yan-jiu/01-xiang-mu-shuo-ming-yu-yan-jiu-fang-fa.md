# 01｜项目说明与研究方法

## 1. 研究对象

当前 Things 3 的 iPhone 版本，Light Mode。研究基线锁定在当前版本行为，不混用旧版截图、iPad、Dark Mode 或历史交互。

一期不以 Apple 深度系统集成为复刻重点，例如 Calendar、Siri、Widget、Shortcuts 等平台绑定能力可在二期独立处理；但只要它们暴露了稳定的产品语义，可以作为数据模型证据。

## 2. 目标级别

目标是 L5 体验级复刻：不仅结构相似，还要覆盖视觉、行为、领域逻辑和连续体验。

研究输出必须同时满足三个视角：

* **产品**：为什么存在、用户意图、信息架构、生命周期；
* **设计**：布局、视觉层级、状态、动效、手势、键盘与焦点；
* **技术**：实体关系、Projection、Command、UI State、组件边界和验收办法。

## 3. 证据等级

* **A**：当前版本真机截图/录屏，可直接观察；
* **B**：Cultured Code 官方文档、Release Notes、App Store、官方技术接口；
* **C**：当前视觉测量、录屏像素测量、跨证据校准；
* **D**：由 A/B/C 支撑的高置信产品或技术推导；
* **E**：为了复刻而提出的工程实现建议，不声称是 Things 内部源码事实。

任何规格都要区分：**观察事实 / 产品解释 / 技术推导 / 复刻建议**。

## 4. 数值规则

录屏中的像素统一标记为 `epx`（encoded pixel），不得直接冒充 iOS pt 或 HarmonyOS vp。颜色从视频取样时只能作为 C 级 Seed，因为会受录屏压缩、色彩空间和编码影响。

无可靠证据的数值使用 `PENDING`；已有初始测量但未冻结使用 `PROVISIONAL`；经过模拟器 Golden 与几何验收后才进入 `VERIFIED`。

## 5. 真机研究工作流

用户提供录屏/截图，模型负责分析，不要求用户肉眼估算延迟、间距或动画时间。一个分支如果缺少真机证据就暂停该结论，不猜测，同时继续所有不依赖该证据的任务。

## 6. 高保真原则

1. 页面是 Projection，不是数据库 Folder。
2. 组织、时间、生命周期、标签和排序必须正交建模。
3. Todo Detail 不是普通独立详情页，而是原列表中的对象展开。
4. Progressive Disclosure、内容优先、低 Chrome、留白本身就是信息架构。
5. 系统默认控件只能在行为合适且视觉可控时使用；核心视觉组件需自定义。
6. 视觉不可只靠“像”，必须用模拟器截图、Inspector、Token、Geometry Contract 与 Golden 自动验收。

## 7. 项目工作流

研究任务按独立验收单元推进；每个正式成果在项目邮件线程同步。GitBook 是长期知识库：把邮件事实、关键聊天和冻结结论重新组织成可阅读、可开发的一本书。
