# 02.7｜开发架构合同：Domain、Query、Command、Presenter

为了让页面和组件不会反向污染产品语义，开发层至少分成以下职责。

## Domain

保存稳定业务事实：Todo、Project、Area、Heading、Checklist、Tag、Repeat Series、Start、Deadline、Lifecycle 等。

Domain 不知道 TodayPage、某个 Picker 是否打开，也不保存 selected / expanded / dragging。

## Command

所有有业务后果的 mutation 通过命令：

```
completeTodo
uncompleteTodo
cancelTodo
deleteTodo
moveTodo
setStart
setDeadline
setReminder
completeProject
cancelProject
moveHeading
pauseRepeat
resumeRepeat
stopRepeat
createNextCopy
```

UI 不直接 `entity.field = value` 绕过约束。

## Query / Projection

Today、Upcoming、Anytime、Someday、Logbook、Deadlines、Repeating 等统一从 Domain 构建 Projection。一个 Command 成功后，各页面重新查询/增量更新，而不是手工通知“把某一行删掉”。

## Presenter / ViewModel

Presenter 把 Domain 语义转换为可渲染数据，例如 DeadlineMeta 只拿 `text / icon / visualState`，不自行判断今天是否逾期。

## UI State

```
expandedTodoId
selectionMode
selectedIds
dragState
activeOverlay
focusedField
scrollPosition
```

这些归 UI/Application presentation 层。

## Shared Engines

Repeat Engine、Projection Engine、Search Index、Context Ordering 必须共享，不允许 TodayPage / ProjectPage 各写一套规则。
