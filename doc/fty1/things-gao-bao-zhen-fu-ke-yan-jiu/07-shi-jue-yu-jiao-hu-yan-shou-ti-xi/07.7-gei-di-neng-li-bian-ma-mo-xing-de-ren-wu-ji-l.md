# 07.7｜给低能力编码模型的任务纪律

开发任务必须足够小，Verified lower component 作为不可随意改动的积木。

正确顺序示例：

1. 实现 ColorTokens；
2. 实现 TodoCheckbox normal/completed；
3. 验两张 Golden；
4. 增加 pressed，但不能破坏前两态；
5. 用 VERIFIED Checkbox 实现 TodoRow normal；
6. 验 Golden；
7. 再增加 long title；
8. 再加入 Metadata；
9. 最后组合 Page Fixture。

失败报告明确“允许修改范围”和“禁止修改范围”。模型不承担开放式重构权限。

最终流水线：

**Evidence → Token → Spec → Fixture → Component → Golden Compare → Verified Component → Page Composition → Page Golden → Motion Test → Regression → Release Candidate**。
